# 2026-05-03 — 调试记录

## 6D 抓取流程一致性修复（7 项）

### Bug 1: 观察位姿不一致
- 根因：run_grasp.py 默认观察位姿 (302,0,421) 与 config.yaml (260,0,300) 不一致
- 修复：run_grasp.py:96 观察位姿默认值对齐 config.yaml `(260,0,300,180,0,90)`

### Bug 2: 标定文件不同步
- 根因：T_camera2end.yaml 在 6d/ 和 graspnet-baseline/ 中内容不同
- 修复：同步 graspnet-baseline 为 6d 最新标定

### Bug 3: episodeApp 版本不一致
- 根因：episodeApp.py 两个目录版本不一致（有/无 DH 参数）
- 修复：同步 graspnet-baseline 为 6d 完整版

### Bug 4: move_xyz_rotation 返回 None
- 根因：episodeApp.py 中 move_xyz_rotation 文档说返回时间值，实际 time.sleep() 后隐式返回 None
- 修复：改为 `return result`（成功）和 `return -1`（失败），移除内部 time.sleep()

### Bug 5: 采集图像在移动到观察位姿之前
- 根因：run_grasp.py 步骤顺序错误
- 修复：步骤重排 — 机器人到位 → 再拍照检测

### Bug 6: 高度过滤太严
- 根因：高度过滤阈值硬编码 `t_camera2base[2] - 10`，与 handler 的 `filter_min_height=-500` 不一致
- 修复：改为 `t_camera2base[2] + 500`

### Bug 7: 角度过滤太严
- 根因：角度过滤 `30°`（默认值），handler 实例属性 `filter_max_angle=90°`
- 修复：`30°` → `90°`

## DeepSeek reasoning_content 400 错误（3 轮修复）

### 尝试 1：收集 reasoning_content
- 根因：DeepSeek V4 thinking mode 要求多轮对话传回 reasoning_content
- 修复：deepseek_provider 收集 reasoning_content → end_turn 事件；context.py 存储；core.py 传递

### 尝试 2：tool_calls 分支丢失 reasoning
- Gatekeeper 发现 P0：finish_reason=="tool_calls" 时 reasoning_parts 被丢弃
- 修复：tool_calls 分支先 yield reasoning 事件再 yield tool_use

### 尝试 3：禁用 thinking mode（最终方案）
- 根因：OpenAI SDK Pydantic 模型可能不透传 DeepSeek 非标准字段 `reasoning_content`，capture 永远取到 None
- 修复：API 请求参数添加 `"thinking": {"type": "disabled"}`，机械臂控制 Agent 不需要 extended reasoning

## check_calibration_status 路径错误
- 根因：ROOT_DIR 和 CALIB_DIR 使用相对路径 `Path("src")`，从 robocode/ 目录启动解析为 `robocode/src/`（不存在）
- 修复：改为基于 `__file__` 的绝对路径

## setting.py 配置修正（4 项）
- 模型 deepseek-chat → deepseek-v4-flash
- base_url 去掉 /v1 后缀
- 添加 PROJECT_ROOT 绝对路径
- env_file 改为绝对路径（子目录启动也能找到 .env）

## ESC 停止机制重写
- 根因：旧实现用 worker 线程 + ctypes 注入 KeyboardInterrupt，线程安全层面不稳定
- 修复：重写为纯 asyncio 架构 — run() async、task.cancel() → CancelledError 原生传播
