# 2026-05-15 — 死代码清理 + 会话管理 + 经验管道修复

## 改动 1: 6d_grasp physics 双写修复

- 问题：`6d_grasp` 工具执行时 physics 数据被写两次——`core.py` 的 PhysicsCollector 写一次（有 tool_call_id），`script_tools.py` 的 `grasp_6d()` 从子进程 JSON 输出再写一次（tool_call_id=None 孤儿数据）
- 影响：`tool_physics_data` 表中同一次抓取有两条记录，一条关联 tool_call，一条是孤儿
- 修复：
  - 删除 `script_tools.py:grasp_6d()` 中 `db.insert_physics_data(tool_call_id=None)` 段
  - 删除 `physics_captured` metric 输出
  - 删除 `make_script_tools(db=, session_id=)` 参数（不再需要）
  - `app.py` 调用改为 `make_script_tools()`

## 改动 2: experience_pending 队列死代码清理

- 问题：`experience_pending` 表 + 6 个相关方法是为异步队列设计的基础设施，但实际 `_run_exp_manage()` 走同步直调路径，从不经过 pending 队列
- 删除内容：
  - `db.py`: `insert_experience_pending`、`get_pending_experiences`、`update_pending_status`、`requeue_failed_pending` 4 个方法 + `experience_pending` 表创建 + 索引
  - `experience_manager.py`: `process_pending`、`_process_one_pending` 2 个方法（约 70 行）
  - `app.py`: `_run_exp_manage` 中 `mgr.process_pending()` 调用 + `_startup_cleanup` 中 `requeue_failed_pending()` 调用
  - 测试：删除 `TestExperiencePendingCRUD`、`TestRetryMechanism`、`test_cleanup_removes_pending_queue`

## 改动 3: 会话 TTL 清理 + 空会话清理

- 问题：sessions/tool_calls 等表永不清除，DB 无限增长；大量 0 次调用的空会话堆积
- 新增：
  - `db.py`: `cleanup_old_sessions(ttl_days=7)` — 删除 >7 天会话 + 级联删除 8 张子表记录
  - `db.py`: `cleanup_empty_sessions(current_session_id)` — 删除 0 次调用的空会话（保留当前）
  - `db.py`: `_delete_session_cascade()` — 安全级联删除（全部 try-except 兼容表未创建）
  - `app.py`: `_startup_cleanup` 中调用上述两个方法
- 实测：48 会话 → 清理 11 个过期 + 18 个空 → 剩余 6 个有效会话

## 改动 4: /resume 交互式箭头选择

- 问题：原 `/resume` 显示列表后需要手动输入 session ID 前缀
- 修改：
  - `slash.py`: `/resume` 无参数时返回 `action="resume_select"` + JSON 会话列表
  - `slash.py`: 提取 `_build_resume_result()` 复用恢复逻辑
  - `app.py`: 新增 `_handle_resume_select()` — 用 `rich.live.Live` + `tty.setcbreak` 实现上下键高亮选择，Enter 确认，q 取消
  - 更新测试 `test_resume_with_session_id` 适配新返回格式
