# 2026-04-28 — 设计决策

## 可行性评估结论
- Phase 1 需要 4 处关键修正，Phase 2 整体可行
- 关键发现：SDK 优先、标定不改脚本/subprocess 编排、抓取是核心价值、DeepSeek V4 Pro 为目标模型

## 设计决策

### LLM Provider → DeepSeek V4 Pro + OpenAI 兼容 API
- LLMProvider 接口改为 OpenAI-compatible function calling 格式
- 目标 DeepSeek V4 Pro

### 工具面分层
- 工具面扩展到 motion/grasping/process orchestration 三层
- Agent 自主判断 CHAT/QUERY/ACTION/CODE 四种模式

### 标定脚本
- 标定脚本作为 subprocess 启动，不改脚本
- 检测只需加 --output_json

### 安全边界
- 文件写和脚本执行需操作者确认
- run_script 改为受控 subprocess 启动器
- headless 风险替换为 GUI 需人在场风险

### 抓取管线分层
- simple_grasp（3D 管线）和 plan_grasp（6D 管线）分层
- Agent 自主选择抓取管线
